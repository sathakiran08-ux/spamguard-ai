# 🛡️ SpamGuard AI

**Intelligent Spam Message Detection Using Machine Learning**

A complete, working spam/ham (not-spam) message detector built with Python,
scikit-learn, and Streamlit. Paste any SMS, email, or text message and get
an instant prediction, backed by a real trained machine learning model
(TF-IDF + Multinomial Naive Bayes) — not a hardcoded demo.

---

## 1. Features

- 🔍 **Single message detection** with a spam/ham prediction and probability gauge
- 📂 **Batch detection** — upload a CSV of messages, download predictions as CSV
- 🕘 **Session-only prediction history** (never saved to disk/database)
- 📊 **Evaluation dashboard** — accuracy, precision, recall, F1-score, confusion matrix
- 📖 **Model Information page** explaining TF-IDF and Naive Bayes in plain English
- 🎨 Modern dark navy/blue dashboard UI with a sidebar, example messages,
  a character counter, and a Clear button
- ⚠️ Robust error handling for empty input, bad CSVs, missing columns, and
  missing model files

## 3. About the dataset (important — read this)

This project ships with `data/spam.csv`, a **practice dataset** generated by
`generate_dataset.py` so that everything runs immediately with **no internet
connection required**. It contains realistic spam and ham message patterns
and is enough to train a genuinely working pipeline end-to-end, but it is
smaller and less diverse than a real-world dataset.

**For the best accuracy, swap in the real SMS Spam Collection dataset:**

1. Go to the UCI Machine Learning Repository:
   `https://archive.ics.uci.edu/dataset/228/sms+spam+collection`
   (it's also mirrored as "SMS Spam Collection Dataset" on Kaggle).
2. Download the dataset and locate the file (often named `spam.csv` or
   `SMSSpamCollection`).
3. Make sure it has two columns:
   - `label` — the string `spam` or `ham`
   - `message` — the text of the message
   
   (If your downloaded file instead has columns `v1`/`v2`, that's fine —
   `train_model.py` automatically renames `v1 → label` and `v2 → message`.)
4. Save/replace the file at `data/spam.csv`.
5. Re-run `python train_model.py` to retrain on the new data.

## 4. Installation (Windows PowerShell + VS Code)

Open **PowerShell** (or the VS Code integrated terminal) and run the
following, step by step:

```powershell
# 1. Create and move into the project folder
mkdir spamguard-ai
cd spamguard-ai

# (If you received this project as a zip, extract it and `cd` into the
#  extracted spamguard-ai folder instead of creating a new one.)

# 2. Create a Python virtual environment
python -m venv venv

# 3. Activate the virtual environment
.\venv\Scripts\Activate.ps1

# If PowerShell blocks the script with an execution-policy error, run this
# once (as a normal user) and then retry the Activate command above:
# Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

# 4. Install dependencies
pip install -r requirements.txt

# 5. Dataset setup
# A practice dataset is already included at data/spam.csv.
# To (re)generate it yourself, run:
python generate_dataset.py
# (Optional but recommended: replace data/spam.csv with the real SMS Spam
#  Collection dataset as described in Section 3 above, for better accuracy.)

# 6. Train the machine learning model
python train_model.py

# 7. Launch the Streamlit application
streamlit run app.py
```

Streamlit will open the app automatically in your browser, usually at
`http://localhost:8501`.

## 5. How the model works (short version)

```
Raw message → Clean text → TF-IDF numeric features → Multinomial Naive Bayes → Spam / Ham
```

- **TF-IDF (Term Frequency–Inverse Document Frequency)** converts each
  message into numbers representing how distinctive each word is — words
  common to spam (like "free", "winner", "urgent") get weighted highly.
- **Multinomial Naive Bayes** is trained on thousands (or, with the sample
  dataset, hundreds) of labeled examples and learns which word patterns are
  associated with spam vs. ham, then estimates the probability of each
  class for new messages.
- The vectorizer is **fit only on the training split**, and evaluated on a
  **held-out test split** it never saw during training, to give an honest
  accuracy estimate and avoid data leakage.
- The model is trained once (`train_model.py`) and **saved to disk**
  (`models/*.pkl`) with `joblib`. The Streamlit app simply **loads** these
  files at startup — it never retrains while you're using it. Only load
  `.pkl` files you trained yourself with this project; never load model
  files from an untrusted source.

See the in-app **Model Information** page for a more detailed,
beginner-friendly explanation.

## 7. Common errors and solutions

| Problem | Solution |
|---|---|
| `ModuleNotFoundError: No module named 'streamlit'` (or similar) | Your virtual environment isn't activated, or dependencies weren't installed. Run `.\venv\Scripts\Activate.ps1` then `pip install -r requirements.txt`. |
| App shows **"Model files were not found"** | You haven't trained the model yet. Run `python train_model.py` from the project folder first. |
| `ERROR: Dataset not found at 'data/spam.csv'` | Run `python generate_dataset.py` to create the practice dataset, or add your own `data/spam.csv` (see Section 3). |
| PowerShell error: *"running scripts is disabled on this system"* | Run `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`, then try activating the virtual environment again. |
| CSV upload says **"No message column found"** | Make sure your CSV has a column literally named `message` (or `text`, `sms`, `content`, `body`). |
| `streamlit: command not found` after activating venv | Reinstall dependencies: `pip install -r requirements.txt`, and confirm the venv is active (you should see `(venv)` in your terminal prompt). |
| Predictions look inaccurate on real-world messages | The included practice dataset is small. Swap in the full real SMS Spam Collection dataset as described in Section 3, then re-run `python train_model.py`. |

## 8. Notes & limitations

- This tool makes **machine-learning estimates only**. It can be wrong in
  both directions (missing real spam, or flagging a legitimate message).
  Never treat a "not spam" result as a guarantee of safety.
- No message you submit is sent to any external server, and nothing is
  stored in a permanent database — prediction history lives only in your
  browser's current session (`st.session_state`) and resets when you
  restart the app.
- No user registration or API keys are required; everything runs locally.
